# DACS Community

Member platform of the UN Decade of Action for Cryospheric Sciences 2025–2034 (version 3.30): member profiles, Working Group spaces, governance, calendar and meeting polls, messages, news, task boards, templates and the logo authorisation desk.

The platform is a static single-page application built with Vite, React and TypeScript. Sign-in and data storage use Firebase Authentication and Cloud Firestore directly from the browser, so the web pages can be served by GitHub Pages while the data remains in the Firebase project `cryohub-eb898`.

## Repository layout

| Path | Content |
| --- | --- |
| `app/` | React pages and components of the Hub |
| `lib/` | Data access, Firebase set-up and pure logic (tested in `tests/`) |
| `components/`, `hooks/` | Shared interface components and hooks |
| `logo-desk/` | Logo authorisation desk and public activity report form |
| `public/` | Static files copied as they are: logos, photos, Terms of Reference, video, templates |
| `firestore.rules`, `firestore.indexes.json` | Database security rules and indexes, deployed to Firebase |
| `.github/workflows/` | Deployment to GitHub Pages and of the Firestore rules |
| `docs/` | Platform reference, Firebase deployment notes, email set-up and release notes (`docs/changelog/`) |

## Publish on GitHub Pages

### 1. Create the repository and push

```bash
git init -b main
git add -A
git commit -m "DACS Community 3.29"
git remote add origin https://github.com/<owner>/<repository>.git
git push -u origin main
```

On a free GitHub plan, GitHub Pages requires a public repository. See "Before making the repository public" below.

### 2. Turn on GitHub Pages

In the repository, open **Settings → Pages** and set **Source** to **GitHub Actions**. The workflow `.github/workflows/deploy-pages.yml` then runs on every push to `main`: it installs the dependencies, runs the unit tests and the Firestore rules tests, builds the site and publishes it. Progress is shown in the **Actions** tab.

The site is published at `https://<owner>.github.io/<repository>/`. The workflow sets the base path automatically, so no file needs to be edited when the repository is renamed.

### 3. Authorise the new address in Firebase

Firebase Authentication only accepts sign-in from listed domains. In the Firebase console, open project **cryohub-eb898 → Authentication → Settings → Authorized domains**, select **Add domain** and enter `<owner>.github.io` (without `https://` or a path). Until this is done, the sign-in page shows "Sign-in is not available on this domain yet".

If the Firebase web API key has HTTP referrer restrictions in the Google Cloud console (**APIs & Services → Credentials**), add `https://<owner>.github.io/*` to them.

### 4. Deploy database rules when a release changes them

GitHub Pages serves the web pages only. The Firestore rules and indexes stay in Firebase and are deployed separately, either from a computer:

```bash
npx -y firebase-tools@14.22.0 deploy --only firestore --project cryohub-eb898
```

or from the **Actions** tab with the manual workflow **Deploy Firestore rules**. That workflow needs a repository secret `FIREBASE_SERVICE_ACCOUNT` holding the JSON key of a Google Cloud service account with the roles **Firebase Rules Admin** and **Cloud Datastore Index Admin**.

## Optional settings

All of these are set under **Settings → Secrets and variables → Actions → Variables**.

| Variable | Use |
| --- | --- |
| `VITE_FIREBASE_API_KEY`, `VITE_FIREBASE_AUTH_DOMAIN`, `VITE_FIREBASE_PROJECT_ID`, `VITE_FIREBASE_APP_ID` | Point the build at another Firebase project. When unset, the values in `.env.example` (project `cryohub-eb898`) are used. |
| `VITE_GOOGLE_ADMIN_CLIENT_ID` | Google OAuth client ID used by the UNESCO Secretariat password reset tool (see `docs/changelog/UPDATE_3_21.md`). |
| `BASE_PATH` | Force a base path, for example `/` when a custom domain is used. Normally not needed. |

### Custom domain

To serve the platform from its own domain (for example `un-cryosphere-decade-community.space`) instead of `github.io`, enter the domain under **Settings → Pages → Custom domain** and follow GitHub's DNS instructions. The site is then served at the root of the domain and the base path becomes `/` automatically. The domain must stay listed in Firebase's authorised domains.

### Password reset links

Version 3.20 set the Firebase email action URL to `https://un-cryosphere-decade-community.space/auth/action`. Password reset emails will keep opening that address. If the platform moves to GitHub Pages without that domain, change the action URL in **Firebase console → Authentication → Templates → Password reset → Customize action URL** to `https://<owner>.github.io/<repository>/auth/action`. Reset links generated by the Secretariat tool already use the address the platform is opened from.

## Differences from Firebase Hosting

1. Deep links (`/poll/<id>`, `/auth/action`) work through a `404.html` copy of the application, generated by every build, because GitHub Pages has no rewrite rules. The page loads normally; the browser receives it with a 404 status code, which members do not see.
2. GitHub Pages does not allow custom HTTP headers. The cache rules and the `X-Frame-Options` header of `firebase.json` therefore do not apply. The logo desk now refuses to run inside a frame from another website, which replaces that header.
3. Firebase Hosting remains fully supported: `npm run build` followed by `firebase deploy --project cryohub-eb898 --only hosting,firestore` publishes the same build at the root of the Firebase domains (see `docs/DEPLOYMENT.md`).

## Before making the repository public

1. The repository contains the source code, the public Firebase web configuration and the Firestore rules, which name the owner account of the UNESCO Secretariat. All of these are already readable by anyone in the files the browser downloads, and the data is protected by Firebase Authentication and the Firestore rules, not by keeping the code private.
2. The private logo register snapshot (`data/logo-register.json`), development screenshots (`shots/`), the previous `dist/` build and local caches were removed from this copy and are listed in `.gitignore`. Keep them outside the repository.
3. The page header asks search engines not to index the platform (`noindex, nofollow`).

## Local development

Node.js 22.12 or later is required.

```bash
npm ci
npm run configure      # creates .env.local from .env.example
npm run dev            # http://127.0.0.1:5173
npm test               # unit tests
npm run build          # type check and production build in dist/
BASE_PATH=/<repository>/ npm run build && npm run preview   # check a GitHub Pages build locally
```

Firestore rules tests need Java 17 or later: `npm run test:rules`. Use of the Firebase emulators is described in `docs/platform-reference.md`.
